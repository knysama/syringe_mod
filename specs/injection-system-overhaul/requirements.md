# 注射系统重构需求

## 1. 目标

把现有“可直接使用的针剂物品”重构为“注射枪 + 安瓿弹药”系统，同时保留现有药效与配方体系，强化药剂包、制作台、混合台和可选 Curios 兼容。

## 2. 兼容与范围

- 保持 Minecraft 1.21.1、NeoForge 21.1.230、Java 21，不升级加载器或依赖版本。
- 保留现有 `*_injection` 注册 ID，将其语义和实现迁移为对应药效的安瓿瓶，避免已有世界中的物品直接丢失。
- 移除原有可直接使用、可堆叠的注射器玩法及其旧实现类；原有药效只通过迁移后的安瓿与注射枪施用。
- 新增独立的 `injection_gun` 物品。
- 保留现有自定义药效、过量使用规则、制作配方、混合配方、JEI 与 EMI 展示。
- Curios 从强制依赖改成可选依赖；未安装 Curios 时模组仍须正常启动。
- 本阶段优先完成逻辑和可用 GUI；正式模型与贴图另行设计。

## 3. 用户故事与验收标准

### R1 注射枪

作为玩家，我希望用一把可重复使用的注射枪装填和施用不同药剂。

1. 当玩家获得注射枪时，系统应使其不可堆叠，并提供 64 次药剂使用耐久。
2. 注射枪应接受原版附魔 ID `minecraft:unbreaking`（简体中文名称“耐久”）；每个附魔等级应确定性增加 16 次可施药容量，不采用原版概率免除损耗的算法。基础、耐久Ⅰ、耐久Ⅱ、耐久Ⅲ的总容量应分别为 64、80、96、112 次。
3. 仅当玩家主手持有注射枪时，换弹键逻辑才应生效；否则系统不得发送换弹请求、打开药剂轮盘或拦截该按键的其他用途。
4. 当玩家主手持有注射枪并短按可重新绑定的换弹键 `R` 时，系统应执行快速换弹。
5. 当快速换弹时，系统应从普通物品栏和玩家携带或装备的药剂包中，选择扫描顺序最靠前的一发有效安瓿。
6. 当玩家按住换弹键达到轮盘触发时间时，客户端应打开必须完整实现的药剂选择轮盘、解除游戏视角对鼠标的捕获并显示可点击的鼠标光标，而不是执行快速换弹；不得以聊天命令、顺序切换或临时列表代替轮盘。
7. 当药剂轮盘打开时，系统应按“安瓿物品 + 完整组件数据”合并显示可用药剂类型及总数量；不同原版药水内容必须显示为不同选项。
8. 当玩家在轮盘中点击一个药剂选项时，服务器应从合法来源中取出该类型的一发安瓿并装入注射枪。
9. 当玩家关闭轮盘但未选择药剂时，系统应保持当前装填状态不变。
10. 当装填完成时，系统应把安瓿的物品与组件数据保存到枪中，并立即从来源移除一发。
11. 当注射枪已有弹药并换装另一发时，系统应先确认旧安瓿有合法的返还位置；有位置时应先把枪膛内未使用的旧安瓿完整退回药剂包或普通物品栏，再取出并装入新安瓿；没有位置时应拒绝整次换弹，且不得覆盖、删除或消耗任一安瓿。
12. 当玩家未瞄准并按下攻击键时，系统应开始一次普通自我注射动作，并在规定动画完成后把已装填药剂施用于玩家自己。
13. 当玩家持续按住使用键进入瞄准状态并按下攻击键时，系统应发射一枚承载已装填药效的投射物。
14. 当投射物命中首个生物时，系统应将对应药效施用于该生物；投射物不造成额外物理伤害。
15. 当投射物发射时，即使最终未命中，系统也应消耗已装填药剂并固定消耗 1 次当前附魔等级对应的施药容量。
16. 当自我注射成功时，系统应消耗已装填药剂并固定消耗 1 次当前附魔等级对应的施药容量。
17. 当没有已装填药剂时，自我注射和射击均应失败，且不得损耗耐久。
18. 当一发药剂被使用时，系统不得返还空安瓿瓶。
19. 当注射枪耐久耗尽时，系统应按普通工具损坏规则销毁注射枪。
20. 所有客户端输入和轮盘选择只能发送操作意图；服务器应重新验证主手物品、装填状态、弹药来源和操作合法性。

### R1A 注射枪动作动画

1. 当玩家开始普通自我注射时，系统应播放 12 tick（0.6 秒）的注射动画：把注射枪移向手臂并完成按压；只有动画完成时才施加药效、消耗药剂并扣除一次容量。
2. 当玩家通过保留的快速使用功能自我注射时，系统应播放 8 tick（0.4 秒）的快速注射动画；只有动画完成时才施加药效、消耗药剂并扣除一次容量。
3. 当玩家执行换弹时，系统应播放 14 tick（0.7 秒）的退旧安瓿和装入新安瓿动画；只有动画完成且服务端再次验证无损换弹事务成功时才提交物品变更。
4. 当玩家发射药剂时，系统应播放 4 tick（0.2 秒）的后坐与复位动画；发射时立即生成投射物、消耗枪膛药剂并扣除一次容量，后坐动画仅表现动作且不能撤销已经发射的药剂。
5. 在普通注射、快速注射或换弹动画期间，玩家应可以移动，但不得再次注射、射击或换弹。
6. 当玩家在普通注射、快速注射或换弹完成前切换物品、死亡、失去有效注射枪或打开其他界面时，系统应取消未完成动作；尚未到提交时点的动作不得消耗药剂、容量或移动安瓿。
7. 第一人称玩家、第三人称本地玩家和其他客户端观察到的动作时序应保持一致；专用服务器不得加载动画渲染类。

### R1B 快速使用功能

1. 现有可重新绑定的快速使用按键 `V` 应保留，并重构为通过注射枪执行的“快速注射”，不得直接调用安瓿药效。
2. 快速注射应遵守相同的服务端校验、药剂冷却、药剂消耗、容量消耗和过量使用规则。
3. 当没有有效注射枪、枪膛与药剂来源均无可用安瓿或玩家正在执行其他注射枪动作时，快速注射应失败且不得消耗物品。

### R2 安瓿瓶

作为玩家，我希望每种药剂以独立安瓿形式储存，并只能作为注射枪弹药。

1. 当安瓿位于普通物品栏或普通容器时，系统应把单组上限限制为 16。
2. 不同物品或不同药水组件的安瓿不得合并为同一组。
3. 当玩家直接对安瓿使用右键或其他原版食用流程时，系统不得饮用、注射或触发药效。
4. 只有注射枪、药剂包和明确允许药剂输入的机器逻辑可以消费或存储安瓿。
5. 现有八种注射药剂的效果、特殊概率和冷却语义应在迁移后保持可识别且可测试。

### R3 药剂包

作为玩家，我希望药剂包成为专门存放安瓿的随身弹药容器。

1. 药剂包应不可堆叠，且只作为物品存在，不注册为可放置方块。
2. 药剂包的内部槽位只接受安瓿标签中的物品，不接受药剂包自身、普通物品或中间药剂混合物。
3. 在药剂包内部，同一种且组件完全相同的安瓿每槽最多保存 64 发。
4. 当安瓿从药剂包取回普通物品栏时，系统应自动遵守普通物品栏每组 16 发的上限。
5. 药剂包应保留现有 3×3、共 9 个内部槽位，除非后续另行调整容量。
6. 当装有物品的药剂包移动、丢弃、死亡掉落或装备到饰品栏时，内部内容应完整保留。
7. 当 Curios 存在时，药剂包应可装备到腰带槽，并可通过现有快捷键打开。
8. 当 Curios 不存在时，与药剂包有关的普通物品栏功能仍应完整可用，且不得发生类加载错误。
9. 现有使用 `SyringeBag` 数据保存的药剂包应提供兼容读取或一次性迁移。

### R4 药剂制作台

作为玩家，我希望药剂制作台像熔炉一样经过可见的加工时间后产出药剂。

1. 当输入匹配制作台配方且输出槽可容纳结果时，系统应持续推进加工进度。
2. 当输入不匹配或输出槽被阻塞时，系统应暂停或重置进度，并不得复制物品。
3. 默认加工时间保留现有 80 tick。
4. 现有制作台配方应继续有效。
5. 制作台应支持把原版药水体系转换为可供注射枪使用的安瓿。
6. GUI 应清楚显示三个输入槽、输出槽、加工进度、当前是否阻塞，以及槽位用途。
7. 自动化插入与提取应继续使用服务端方块能力，并只允许从输出槽提取成品。

### R5 药剂混合台

作为玩家，我希望药剂混合台经过加工时间把两种药剂材料混合成结果。

1. 当两个输入匹配混合配方且输出槽可容纳结果时，系统应持续推进加工进度。
2. 默认加工时间保留现有 80 tick。
3. 现有混合台配方应继续有效。
4. GUI 应清楚显示两个输入槽、输出槽、加工进度、当前是否阻塞，以及槽位用途。
5. 自动化不得从输入槽提取或向输出槽插入物品。

### R6 资源、兼容与验证

1. 所有新增用户可见文本应同时提供 `en_us`、`zh_cn` 和自然表达的 `zh_tw`。
2. JEI 和 EMI 存在时，应展示保留及新增的制作台、混合台配方。
3. 专用服务器启动时，不得加载客户端输入、渲染或 Screen 类。
4. `compileJava`、数据生成和完整 `build` 应成功。
5. 应至少验证：短按 `R` 快速换弹、长按 `R` 打开轮盘、轮盘选择与取消、装填顺序、已装填药剂的无损更换、左键自注射、瞄准射击、空枪行为、基础 64 次及耐久Ⅰ/Ⅱ/Ⅲ对应的 80/96/112 次容量、安瓿 16 堆叠、包内 64 堆叠、非法物品拒绝、Curios 有无两种启动路径、机器输入堵塞与输出堵塞。

## 4. 待确认的产品决策

### D1 换弹键与药剂轮盘（已确认）

已按用户意见调整为：

- 左键且未瞄准 = 立即给自己注射；
- 按住右键瞄准时按左键 = 立即射击；
- 短按 `R` = 自动换装扫描顺序最靠前的药剂；
- 长按 `R` = 打开药剂轮盘并点击指定药剂。

建议长按阈值为 8 tick（0.4 秒）。轮盘为不暂停游戏的 HUD Screen，打开时释放并显示鼠标光标；每页最多显示 8 种药剂，药剂超过 8 种时使用鼠标滚轮翻页。用鼠标点击扇区确认换弹，`Esc` 或松开 `R` 但未点击时取消并重新捕获鼠标。

跨容器扫描采用药剂包优先：

1. Curios 腰带槽中的药剂包；
2. 普通物品栏内的药剂包，按物品栏位置及包内槽位顺序；
3. 快捷栏从左到右；
4. 主物品栏从左上到右下。

### D2 “添加原版药水的制作”（已确认）

按推荐方案实现为新增一种带原版 `POTION_CONTENTS` 组件的通用安瓿：

- 制作台可把任意原版普通药水转换成相同效果的安瓿；
- 不接受喷溅药水或滞留药水；
- 相同药水安瓿可堆叠，不同药水组件自然不能堆叠；
- 注射枪命中时应用原版药水的全部效果。

不在制作台中复制原版酿造台的完整酿造链。

### D3 投射参数（已确认）

首版采用直线高速投射物、约 32 格实用射程、无重力或极弱下坠、10 tick 射击冷却，命中任意 `LivingEntity` 后消失。

### D4 燃料（已确认）

两台机器继续保持无燃料加工；“类似熔炉”只表示需要等待和显示 80 tick 加工进度。

### D5 快速使用查找注射枪（已确认）

快速使用允许使用未拿在手上的注射枪：优先使用主手注射枪，主手没有时再按快捷栏、主物品栏顺序寻找第一把有效注射枪，并在动画期间临时渲染该注射枪。服务端在动作开始和 8 tick 提交时都应重新验证该枪仍位于玩家库存中且是同一堆栈。

## 5. 非目标

- 本阶段不制作最终 Blockbench 模型和正式贴图。
- 本阶段不增加多发弹匣、卸弹、弹药选择菜单、范围伤害或自动追踪。
- 本阶段不升级 Minecraft、NeoForge、Gradle 或第三方模组版本。

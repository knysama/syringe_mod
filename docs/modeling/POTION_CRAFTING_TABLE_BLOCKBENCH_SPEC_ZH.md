# 药剂制作台 Blockbench 精确建模操作说明书

> 适用项目：`syringe_mod`  
> 目标资产：单方块药剂制作台  
> 建模软件：Blockbench  
> 推荐格式：Java Block/Item  
> 参考三视图：[`reference/potion_crafting_table_three_view.png`](reference/potion_crafting_table_three_view.png)

---

## 1. AI 执行总指令

严格按照本说明书给出的尺寸、位置、数量、分组和颜色建模，不要根据常见“炼药台”“厨房”“实验室”印象自行改造。

模型的核心外观为：

- 一个完整放入 Minecraft 单格方块范围的科技型工作台；
- 长边正好占满 16 个模型单位；
- 下部是白灰色设备机柜；
- 台面左侧放置一块与水浴锅配套的正方形盖子；
- 台面中部是正方形水浴锅，锅内有 2×2 药剂位；
- 后部有五瓶大型药水；
- 右后部有三支细长安瓿瓶；
- 科技感来自设备结构、嵌板、控制器、规则分区和材料对比，不使用大量灯条或发光污染。

必须遵守：

1. 只使用正交长方体和必要的水平 2D 平面。
2. 禁止圆柱、球体、斜面、倒角、曲面和高面数网格。
3. 所有元素必须位于一格方块的 `0–16` 坐标范围内。
4. 不缩放成双格工作台，也不把部件挤压成过窄的微缩景观。
5. 使用逐面 UV，不使用自动 Box UV 作为最终结果。
6. 像素比例统一，不出现高分辨率小字、平滑渐变或抗锯齿。
7. 三视图的结构优先级高于任何自由发挥。

## 2. 工程设置

### 2.1 新建工程

- Format：`Java Block/Item`
- Texture Width：`64`
- Texture Height：`64`
- Box UV：关闭
- Ambient Occlusion：开启，用于原版方块式接触阴影
- UV Rotation：只允许 `0°`、`90°`、`180°`、`270°`
- 模型根组名称：`potion_crafting_table_root`

### 2.2 坐标约定

| 轴 | 含义 | 范围 |
|---|---|---|
| X | 左 → 右 | 0–16 |
| Y | 下 → 上 | 0–16 |
| Z | 前 → 后 | 0–16 |

- 模型默认朝向：`NORTH`
- 正面：靠近 `Z=0`
- 背面：靠近 `Z=16`
- 根基准点：`[8, 0, 8]`
- 整体最大宽度：`16`
- 主体深度：约 `12.5`
- 最高点：`Y=14.5`

不要改变坐标轴含义。后续方块朝向应由 blockstate 的 Y 旋转处理，不要复制四套模型。

建议使用三张纹理：

| `potion_crafting_table_vessels.png` | 32×32 | 所有药水瓶、安瓿、瓶盖和液体色块 |

### 10.2 主纹理图集建议

`potion_crafting_table.png` 的逻辑分区：

| UV 区域 | 用途 |
|---|---|
| `0–16, 0–16` | 暖白色外壳 |
| `16–32, 0–16` | 白灰结构边框和高光面 |
| `32–48, 0–16` | 深色检修面板、锁扣、硬件 |
| `48–64, 0–16` | 散热格、药瓶架背板 |
| `0–16, 16–32` | 方形盖子 |
| `16–32, 16–32` | 水浴锅、锅沿 |
| `32–48, 16–32` | 台面、底座、设备脚 |
| `48–64, 16–32` | 青色状态窗、控制器 |
| `0–64, 32–64` | 各方向侧面、底面及重复结构备用区 |

这是区域规划，不要求每个长方体独占一块 UV。重复材质允许共用 UV。

### 10.3 药瓶纹理图集建议

`potion_crafting_table_vessels.png`：

| UV 区域 | 内容 |
|---|---|
| `0–20, 0–8` | 五个大瓶颜色变体，每个约 4×8 |
| `0–16, 8–16` | 四个水浴锅小瓶，每个约 4×8 |
| `0–12, 16–24` | 三支安瓿，每个约 4×8 |
| `16–24, 8–16` | 通用玻璃边缘和高光 |
| 其余区域 | 瓶盖、深色瓶体、备用像素 |

### 10.4 逐面 UV 原则

每个长方体都要检查六个面：

- 大面积正面、顶面：尽量遵循 `1 模型单位 ≈ 1 纹理像素`；
- 极小部件允许使用最少 1 像素宽的面；
- 相同材质的左右侧面可以镜像共用；
- 顶面要比正面亮一级；
- 侧面保持基础色；
- 底面比侧面暗一级；
- 不允许把一个 1 像素图块拉伸成明显的 8×8 模糊区域；
- 不允许任意角度 UV；
- 不允许 UV 越界。

为避免像素错位，UV 坐标尽量落在整数，禁止无必要的小数 UV。

### 10.5 玻璃表达

玻璃瓶使用像素化“假透明”方案：

- 外轮廓：浅青灰或灰白；
- 内部窗口：较深的蓝灰；
- 药液：单一主色加一档亮色和一档暗色；
- 高光：最多一条 1 像素竖线或角部像素；
- 边界完全硬边；
- 不使用平滑透明渐变；
- 优先使用完全不透明或二值 Alpha。

如果实际资源采用透明像素，方块需使用 `cutout` 渲染层。除非确有必要，不使用 `translucent`，以避免排序问题。

## 12. 像素艺术和光照规则

1. 采用有限调色板。
2. 每种材料通常只使用亮、中、暗三档。
3. 假定光源从前上方偏左照射。
4. 顶面最亮，左/前面为中间色，右/底面更暗。
5. 所有明暗交界必须落在像素边界。
6. 禁止软笔刷、模糊、噪点覆盖、环境渐变和自动抗锯齿。
7. 必须做过渡时，只允许规则棋盘格抖动。
8. 青色只用于小状态窗和控制器，不扩展成环绕灯带。
9. 不在纹理中绘制不可读的小字或伪文字。

## 13. 推荐制作顺序

### 阶段 A：灰模

1. 创建主体、台面、底座和四脚。
2. 切换正交前视图，确认宽度为 16、高度不超过 14.5。
3. 切换正交顶视图，确认所有内容位于 0–16。
4. 创建正面检修面板和右侧散热板。

此阶段只用灰色，先检查轮廓。

### 阶段 B：台面设备

1. 按坐标创建左侧方盖。
2. 按坐标创建中部正方形水浴锅。
3. 添加水面、2×2 托板和四个小瓶。
4. 添加锅前控制器。

检查盖子和水浴锅的平面尺寸是否完全一致。

### 阶段 C：后部陈列

1. 创建后部五瓶架。
2. 先做一瓶完整大瓶，复制并沿 X 轴移动。
3. 分别重命名并指定橙、黄、绿、蓝、紫 UV。
4. 创建右后安瓿架。
5. 制作一支安瓿，复制为三支并指定紫、绿、黑 UV。

复制后必须应用准确坐标，不要手动目测拖放。

### 阶段 D：UV

1. 创建三张纹理或合并图集。
2. 为主体逐面分配 UV。
3. 检查顶部、前部、右侧三个主要视角。
4. 给瓶子分配对应液体颜色。
5. 检查所有小面至少有一个完整像素。

### 阶段 E：像素绘制

1. 先铺主色。
2. 再添加硬边阴影。
3. 绘制边框、凹槽和玻璃高光。
4. 最后添加少量青色状态像素。
5. 关闭纹理过滤，以最近邻方式检查。

### 阶段 F：清理

- 删除完全被遮住且永远不可见的内部面；
- 删除重叠方块；
- 修复共面造成的闪烁；
- 保证没有任何元素超出 `0–16`；
- 保证所有分组和元素命名唯一；
- 保证 Rotation 全部为零。

## 16. 游戏端渲染注意事项

- 该模型仍只占用一个方块位置；
- 模型轮廓不是完整立方体，方块类应保持非完整碰撞/视觉形状的设计；
- 如果纹理存在透明玻璃像素，注册 `cutout` 渲染层；
- 装饰瓶面通常不要设置 `cullface`；
- 只有确实紧贴完整方块边界且可安全剔除的面才设置 `cullface`；
- 纹理必须使用最近邻采样和 Minecraft mipmap；
- 当前静态模型不包含制作动画；
- 未来若需要工作状态变化，保留 `water_bath`、`sample_bottles`、`indicator` 等语义分组作为拆分依据。
